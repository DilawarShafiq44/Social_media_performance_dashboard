# 📐 DAX Measures — Social Pulse Dashboard

All measures below are stored in the `_Measures` table of the Power BI semantic model.
Created and deployed using Claude AI via a live MCP server connection to Power BI Desktop.

---

## Totals

### Total Posts
```dax
Total Posts = COUNTROWS(fact_posts)
```
Counts the total number of posts in the dataset.

---

### Total Engagements
```dax
Total Engagements = SUM(fact_posts[Engagement])
```
Sums total engagement across all posts.


## Time Intelligence

### Engagement Previous Month
```dax
Engagement Previous Month = 
CALCULATE(
    [Total Engagements],
    DATEADD(Dim_Date[Date], -1, MONTH)
)
```
Returns total engagement shifted back exactly one month using `DATEADD`, allowing accurate comparisons even for partial date ranges (day-level, MTD, custom periods) — not just full calendar months.

---

### Engagement MoM % Change
```dax
Engagement MoM % Change = 
DIVIDE(
    [Total Engagements] - [Engagement Previous Month],
    [Engagement Previous Month]
)
```
Calculates month-over-month engagement growth or decline as a percentage. Uses `DIVIDE` instead of `/` to safely handle division-by-zero errors.

## Design Notes

- All measures live in a dedicated `_Measures` table (best practice — keeps measures separate from data tables for easier navigation).
- `Dim_Date` is a single, governed calendar table — after auditing the model, 9 redundant hidden date tables (auto-generated by Power BI's Auto Date/Time setting) were identified and removed to keep time-intelligence functions reliable and consistent.
- `DATEADD` was chosen over `PREVIOUSMONTH` for period comparisons, since it correctly handles partial date ranges (e.g., MTD or single-day filters) rather than only full calendar months.
